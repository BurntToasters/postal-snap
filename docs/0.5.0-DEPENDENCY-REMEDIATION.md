# Postal Snap 0.5.0 dependency remediation

The October 16, 2026 audit found seven RustSec advisories in the updater's
target-dependent graph: four for `rustls 0.23.45` and three for `zip 4.6.1`.
The release audit gate denies warnings; its acknowledged Tauri/GTK advisory
list was not changed.

`rustls` is now `0.23.46`, the version patched for RUSTSEC-2026-0346 through
-0349. It was published at `2026-10-14T09:54:15Z`, so its 72-hour eligibility
time was `2026-10-17T09:54:15Z`. The safe Cargo wrapper was given the exact
`rustls@0.23.46` emergency override with a written reason; no global age rule
was lowered.

The crates.io `tauri-plugin-updater 2.14.0` release still declares Windows
`zip = "4"`. The official Tauri plugins-workspace v2 revision
[`f36ba7ba48695776bc11cce0bfdc45678ec24f72`](https://github.com/tauri-apps/plugins-workspace/commit/f36ba7ba48695776bc11cce0bfdc45678ec24f72)
keeps the updater package at `2.14.0` and changes that dependency to `zip =
"9"`. `Cargo.toml` pins this exact revision. The safe updater accepted it only
with the exact Git commit override and written security justification. The
selected `zip 9.0.3` was published at `2026-10-13T19:55:20Z`, more than 72
hours before resolution.

The source change retains the existing optional `direct-updater` feature gate.
The updater's minisign signature verification remains enabled in the pinned
source; Store builds continue to omit the updater feature. No advisory ignore
was added. Cargo source transitions use the reviewed baseline workflow in
[`DEPENDENCY_UPDATES.md`](DEPENDENCY_UPDATES.md), which compares the old
manifest and original lock in a disposable workspace using locked metadata.

The matching JavaScript updater plugin is pinned in `package.json` and
`package-lock.json` to exact version `2.14.0`. Tauri rejects the prior
`@tauri-apps/plugin-updater 2.13.3` against Rust updater `2.14.0`; matching
versions are required for `tauri info` and release builds. npm published
`2.14.0` at `2026-10-14T19:20:06Z`, making it eligible under the 72-hour rule
at `2026-10-17T19:20:06Z`. This repair used the exact
package target and `--min-release-age=3`, using a one-invocation
`--min-release-age-exclude=@tauri-apps/plugin-updater` exception approved for
this compatibility fix. The `.npmrc` age limit remains unchanged, the
exclusion was not persisted, and the package-lock diff changes no other
dependency versions. `npm run tauri -- info` now reports Rust and JavaScript
updater packages at `2.14.0`, and the regenerated npm license notices include
the new package version.

The exact source and age overrides apply to these dependency repairs only.
`Cargo.lock` records the updater Git URL and full commit, `rustls 0.23.46`, and
`zip 9.0.3`; notices are regenerated from that lockfile.

Local verification passed: `npm run audit:cargo` scanned 679 locked crates with
no findings; `cargo tree --target all` contains rustls 0.23.46 and zip 9.0.3,
with rustls 0.23.45 and zip 4.6.1 absent. Store feature trees (`msstore` and
`mas`, both with default features disabled) omit updater and process plugins.
`npm run licenses:cargo` generated 678 Cargo entries. The safe-update and policy
suite passed 94 checks, and `npm run test:release-assets` passed 186 checks.

## October 17, 2026 follow-up

RUSTSEC-2026-0373 (CSS `url()` case-insensitive matching) affects `ammonia`
4.2.3, the received-HTML sanitizer. `src-tauri/Cargo.lock` now pins the exact
patched `ammonia 4.2.4` (published 2026-10-17T03:45:58Z; 72-hour eligible
2026-10-20T03:45:58Z). The safe Cargo wrapper accepted it only through the
exact `--allow-young ammonia@4.2.4` override with a written reason; no global
age rule changed and no advisory was ignored.

RUSTSEC-2026-0370, -0371, and -0372 are informational "unmaintained"
warnings for the deprecated zbus 5.x split crates (`zvariant`,
`zbus_names`, `zvariant_derive`). They reach Postal Snap through the Tauri
notification, keyring, and opener plugins on Linux; the replacement is zbus 6,
which those plugins do not yet adopt, so no patched release exists to take.
The three exact IDs are acknowledged in `scripts/audit-cargo.js` with that
reason, next to the long-standing GTK/glib entries, and must be removed when
the plugins move to zbus 6.
