# Postal Snap architecture

The React/Vite frontend owns presentation only. Every mail, cache, credential, and network operation crosses a narrow typed Tauri command boundary into Rust.

Each account has a serialized actor lock that owns mutations and its pooled session. When supported, a separate read-only watcher examines INBOX and idles only to wake the actor; connection limits or unsupported IDLE use the in-actor path. IMAP uses verified TLS (or mandatory STARTTLS), UID/UIDVALIDITY synchronization, SPECIAL-USE folder discovery, and a five-minute all-folder refresh; servers without IDLE use a two-minute poll. SMTP submission uses `lettre`. A definite refusal (a 4xx reply, or a connection that never opened) returns the row to `queued` for an automatic retry with backoff; a 5xx reply or failed TLS becomes `needs_attention` marked not sent; any uncertain result (a connection lost mid-session) stays in `needs_attention` and is never automatically resent.

Folder discovery uses LIST-STATUS (RFC 5819) when the server advertises it: one `LIST "" "*" RETURN (SPECIAL-USE STATUS (...))` returns every folder with its counts. The reply is read raw until the tagged completion, so async-imap's 100-item unsolicited buffer cannot drop a status. A NO, BAD, malformed, or oversized reply falls back to plain LIST plus one STATUS per folder; a timeout or socket error also discards the session before that fallback. When the server advertises ID (RFC 2971), each new connection sends only `("name" "Postal Snap")`: no version, OS, or host. The reply is ignored, and a NO or BAD never fails the connection.

SQLite stores account server configuration, folders, envelopes, decoded bodies, FTS5 indexes, sync cursors, drafts, outbox state, and offline operations. Envelope sync can cache a bounded partial body; the reader fetches the complete message before source view, export, forwarding, or attachment access. The `keepAttachmentsOffline` setting defaults to off and can keep attachment content available without a connection. Passwords never enter SQLite. Schema changes use transactional `PRAGMA user_version` migrations; v1 attachment grants referenced by drafts or outbox rows are preserved during migration, while orphan grants are discarded. The default cache policy is 90 days/1 GB with LRU eviction, while drafts and unsent records are protected.

On Windows the database and its WAL/shared-memory files, the message cache, and draft attachments live under the local (non-roaming) app data directory; `settings.json` stays in the roaming config directory. That keeps roaming profiles and FSLogix/Citrix/VMware profile containers from copying a live SQLite database, and mailbox passwords use local-machine vault persistence so keyring entries do not follow the profile.

Mailbox totals and unread counts come from IMAP `STATUS` and remain separate from cached-envelope counts. Small local deltas keep the UI immediate until the next authoritative status refresh. Message lists use stable date/UID cursors. Cached UID reconciliation runs in bounded chunks across the complete cache, and missing server folders are removed only after a complete successful discovery pass.

Drafts are committed locally before remote work. Compatible Drafts folders receive revisioned Message-IDs; a new revision is confirmed before the old UID is deleted. Server conflicts become separate recovered drafts. Outgoing MIME and Message-ID are persisted before SMTP starts. Only never-attempted `queued` rows replay automatically; uncertain attempts become `needs_attention`, while a failed Sent-folder copy becomes `sent_copy_pending` and can retry without resending SMTP.

Received HTML is sanitized in Rust with ammonia before it is stored or returned over IPC, then sanitized again with DOMPurify before entering a sandboxed iframe (`allow-same-origin allow-popups`, never `allow-scripts` or `allow-popups-to-escape-sandbox`). Its CSP allows no scripts or network requests. WebKit runs no listeners inside that scriptless frame, so frame links carry their real target with `target="_blank"`; the native navigation and new-window hooks always deny the popup and emit only an http(s)/mailto URL to the reader, which runs the normal inspection and confirmation. Consent-based remote image requests are proxied through Rust after DNS/IP/redirect validation. Official EasyList/EasyPrivacy network-rule matching and a local TweetFeed reported-threat check run before DNS unless the matching Advanced preference is off. Image consent, certificate/TLS rules, and private-network blocking stay on. External HTTP(S) links use the same threat check when that preference is on, then confirmation, then a Rust opener. The privileged webview CSP keeps `script-src 'self'` with no `unsafe-eval`; `style-src 'unsafe-inline'` is accepted because Tiptap/ProseMirror inject a runtime style element and a few controls use inline style attributes. Printing never uses an unsandboxed frame. On Windows and Linux the letter prints from a sandboxed same-origin frame (`allow-same-origin allow-modals`, no scripts) that is removed after printing. macOS WebKit ignores `print()` from frames, so macOS prints the window natively (`print_webview`) while `@media print` shows only a sandboxed `allow-same-origin` host frame sized to its content. See [CONTENT_BLOCKING.md](CONTENT_BLOCKING.md) and [THREAT_BLOCKING.md](THREAT_BLOCKING.md).

Distribution features are compile-time/runtime detected. Direct packages use signed GitHub updater manifests. Microsoft Store, Mac App Store, and Flatpak editions report store-managed updates and do not initialize or expose the Tauri updater.

On Windows the mailbox window is frameless with HTML caption controls and a native Snap-layout hit-test overlay over Maximize (the same WebView2 `HTMAXBUTTON` approach as IYERIS). Native application menus stay on macOS (system menu bar) and Linux (decorated GTK window). Windows must not call `app.set_menu`: muda's Win32 menubar is painted on `WM_NCACTIVATE` and shows through the transparent WebView2 as Postal Snap / File / Edit / Message / View. Mail keyboard shortcuts on Windows are handled in the React shell. Product right-click menus are HTML portals in the webview, not a native app menubar. `closeToTray` (default on) hides the window to a Windows notification-area icon or macOS menu bar extra instead of quitting; Linux ignores the field and still quits on close. On macOS a window closed to the menu bar also leaves the Dock (accessory activation policy) until it is reopened. Left-clicking the tray or menu bar icon toggles the window: it hides the window in use and otherwise shows and focuses it. macOS decides by focus (a menu bar click keeps focus); Windows decides by visibility (the taskbar takes focus first). Right-click opens the menu. A downloaded update installs quietly on quit (without relaunching) or, after the window has waited 60 seconds in the tray or menu bar (timed in Rust, since hidden webviews throttle timers), in the background; a short-lived `update-relaunch` marker in app data tells the relaunched process to start hidden.

Direct-download editions store the updater check cadence in `settings.json` as `updateCheckInterval` (startup plus every 6 hours by default). Rust times the periodic checks on the wall clock (`update_schedule.rs`), so time asleep counts and a hidden tray window still checks; a failed check retries after 10 minutes. Store and Flatpak editions ignore that field and keep store-managed updates.

Direct editions also choose an update channel at runtime with `updateChannel` (`auto`, `stable`, or `beta`; default `auto`) in Settings > Advanced. Auto follows the installed build, where a version containing `-` is beta. Beta clients call the updater with target `<platform>-beta` and read `latest-<target>-beta-<arch>.json`. Switching channel discards a downloaded update, Beta to Stable never downgrades, and settings import never changes the channel. Store and Flatpak editions hide the picker.

Window glass is chosen per platform in `window_fx.rs`. Windows applies Mica through public APIs and falls back to an opaque background; Acrylic is not used because it lags on resize. macOS applies an `NSVisualEffectView` sidebar material only when built with the `macos-vibrancy` Cargo feature, which enables Tauri's private API. Only direct (DMG/ZIP) macOS builds opt in. Mac App Store, Microsoft Store, and Flatpak builds never enable that feature, and a `compile_error!` guard rejects the combination with `mas`. Every Tauri config keeps `macOSPrivateApi` false. Traffic-light buttons are positioned by `MAC_TRAFFIC_LIGHTS` in `main.rs`. Linux stays opaque. The frontend (`src/window-fx.ts`) listens for reduced-transparency and forced-colors changes and removes its handlers before re-adding them.

Opened email files use an in-memory store in `opened_mail.rs`. Files arrive only from OS open events, first-launch or single-instance argv, or Rust dialogs, and `open_paths` takes them from there. The store is a token LRU of at most 8 messages and 128 MiB; each token is a UUID. Files must be regular, non-symlink `.eml` files of at most 50 MiB, read through `bounded_file`. The viewer uses the same ammonia, DOMPurify, and sandbox path as the reader, with remote images blocked. Nested `message/rfc822` parts are listed for viewing and are not rendered automatically. Attachment ids are scoped to the token, so one opened message cannot reach another.

PDF previews (`pdf_preview.rs`) render in memory with `hayro`, a pure-Rust renderer. They take at most 20 pages, at most 1600 px wide and 4 million pixels per page, with a 10-second timeout, and run on a blocking task inside `catch_unwind`. Each PNG passes `detect_image_mime` before it becomes a data URL. Nothing touches disk, and PDF bytes never reach the privileged webview.

Mailbox export and import (`mbox.rs`, `commands/import_export.rs`) use mboxrd framing and run only after Rust file dialogs. Export runs under the account lock, writes oldest first with `>From ` quoting, and skips messages over 50 MiB while counting them. Import streams a file of at most 1 GiB and at most 10,000 messages, parses each one with `mail-parser`, and appends batches of 50 (or 32 MiB) as `\Seen` through `mail/append.rs`. Both directions report progress events with ids only and can be canceled. Partial files are removed on failure or cancel. Errors never include names or paths.

New-mail notifications are routed in `notify.rs`. Each notice reserves an id, and a bounded map of 32 entries links that id to an account and message. A tap shows the main window and emits `notification-open` with ids only. Accounts with `notify_new_mail` off are skipped, and private notifications keep sender and subject text out of the native banner.

Colored flags and junk training map to IMAP keywords in `mail/keywords.rs`. Colors 0 through 6 (red, orange, yellow, green, blue, purple, gray) map to bits 1, 2, and 4 in `$MailFlagBit0/1/2`, which is Apple Mail's encoding. Setting a color also stores `\Flagged`. Clearing removes every bit. A color change is written only when PERMANENTFLAGS allows keywords. Bit pattern 7 reads as red. Search `flag:<color>` maps to `FLAGGED` plus `KEYWORD` or `UNKEYWORD` searches. Junk training stores `$Junk` or `$NotJunk` on user moves into or out of Junk, sends the STORE before the MOVE, and treats it as best effort. Rule moves send none.

The typed event boundary includes sync state, folder-count, message-change, draft-sync, and outbox events. Event payloads contain opaque IDs and safe states, never message content or credentials.

The database runs with `secure_delete` on. Clearing downloaded mail, removing an account, or erasing all data attempts `VACUUM` plus a WAL truncate while reads are paused. Account removal reports deferred cleanup; reset and cache clearing report failure if compaction cannot finish. A failed compaction records a startup retry marker when the filesystem permits it. Removed mail may remain in the WAL until cleanup succeeds. A newer-schema or unreadable database opens an empty in-memory stand-in and the window explains the problem; account creation and erase are refused until a restart opens the real file. The search-index check runs in the background after the window opens. Just before a downloaded body is parsed, an unfinished-parse count is committed and reset afterwards. Two unfinished parses in a row, or one caught parser panic, quarantine that message: prefetch skips it and the reader shows it as unreadable. A single quit mid-parse is forgiven. Definite "try later" SMTP replies retry with backoff (1 minute doubling to 60) and move to `needs_attention` after 8 tries.

Every database operation runs through the shared `database_operations!` boundary. In the app's multithread Tokio runtime, `block_in_place` lets other tasks run during both queries and lock waits. Plain synchronous callers, including current-thread test runtimes, run inline. New operation impl blocks must use this boundary. Schema migrations run ordered version steps inside one transaction. Known outbox reasons are stored as codes; legacy details remain readable.

List, detail, search, and account reads use a separate read-only WAL connection, so they do not wait behind sync writes; housekeeping on those paths (snooze pruning, eviction recency) is skipped when the writer is busy. Release builds unwind on panic: a panicking parse or task fails alone, the DB lock recovers from poisoning (rusqlite rolls back the open transaction), and a parser panic quarantines that message. Message rows are virtualized and use `content-visibility: auto`, so off-screen rows skip layout and paint while preserving list accessibility metadata.

The frontend keeps composition components small: mailbox controls are under `src/components/mail/`, reader actions and notices under `src/components/reader/`, and composer extensions and hooks under `src/components/composer/`. Rust IMAP connection, folder, parse, pool, sync, and watcher code is grouped under `src-tauri/src/mail/`; the top-level files remain facades and shared boundaries. SettingsDialog state and effects are split across six hooks for account management, capabilities, filter rules, storage, threat protection, and updates. Settings mutations use the shared `useSettingsSave` queue. The all-inboxes badge reuses `get_account_inbox_counts` (`getAccountInboxCounts`) and sums existing per-account Inbox unread counts; it does not create a unified mail view.

Density tokens live in `src/styles/variables.css`. `:root` is the Normal set (the default); `:root[data-density="comfortable"]` and `:root[data-density="compact"]` override it. Compact keeps its own block, and comfortable keeps the pre-0.5.2 values. `src/styles/density.css` holds only layout rules tokens cannot express. At 100% text the sizes must order compact ≤ normal ≤ comfortable; the density matrix spec `e2e/density-matrix-0.5.2.spec.ts` checks that ordering and writes its measurements as an artifact.
