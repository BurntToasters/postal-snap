# Postal Snap architecture

The React/Vite frontend owns presentation only. Every mail, cache, credential, and network operation crosses a narrow typed Tauri command boundary into Rust.

Each account has a serialized actor lock. IMAP uses verified TLS (or mandatory STARTTLS), UID/UIDVALIDITY synchronization, SPECIAL-USE folder discovery, and a two-minute background fallback. SMTP submission uses `lettre`. A definite refusal (a 4xx reply, or a connection that never opened) returns the row to `queued` for an automatic retry; a 5xx reply or failed TLS becomes `needs_attention` marked not sent; any uncertain result (a connection lost mid-session) stays in `needs_attention` and is never automatically resent.

SQLite stores account server configuration, folders, envelopes, decoded bodies, FTS5 indexes, sync cursors, drafts, outbox state, and offline operations. Passwords never enter SQLite. Schema changes use transactional `PRAGMA user_version` migrations; v1 attachment grants referenced by drafts or outbox rows are preserved during migration, while orphan grants are discarded. The default cache policy is 90 days/1 GB with LRU eviction, while drafts and unsent records are protected.

On Windows the database and its WAL/shared-memory files, the message cache, and draft attachments live under the local (non-roaming) app data directory; `settings.json` stays in the roaming config directory. That keeps roaming profiles and FSLogix/Citrix/VMware profile containers from copying a live SQLite database, and mailbox passwords use local-machine vault persistence so keyring entries do not follow the profile.

Mailbox totals and unread counts come from IMAP `STATUS` and remain separate from cached-envelope counts. Small local deltas keep the UI immediate until the next authoritative status refresh. Message lists use stable date/UID cursors. Cached UID reconciliation runs in bounded chunks across the complete cache, and missing server folders are removed only after a complete successful discovery pass.

Drafts are committed locally before remote work. Compatible Drafts folders receive revisioned Message-IDs; a new revision is confirmed before the old UID is deleted. Server conflicts become separate recovered drafts. Outgoing MIME and Message-ID are persisted before SMTP starts. Only never-attempted `queued` rows replay automatically; uncertain attempts become `needs_attention`, while a failed Sent-folder copy becomes `sent_copy_pending` and can retry without resending SMTP.

Received HTML is sanitized in Rust with ammonia before it is stored or returned over IPC, then sanitized again with DOMPurify before entering a sandboxed iframe (`allow-same-origin allow-popups`, never `allow-scripts` or `allow-popups-to-escape-sandbox`). Its CSP allows no scripts or network requests. WebKit runs no listeners inside that scriptless frame, so frame links carry their real target with `target="_blank"`; the native navigation and new-window hooks always deny the popup and emit only an http(s)/mailto URL to the reader, which runs the normal inspection and confirmation. Consent-based remote image requests are proxied through Rust after DNS/IP/redirect validation. Official EasyList/EasyPrivacy network-rule matching and a local TweetFeed reported-threat check run before DNS unless the matching Advanced preference is off. Image consent, certificate/TLS rules, and private-network blocking stay on. External HTTP(S) links use the same threat check when that preference is on, then confirmation, then a Rust opener. The privileged webview CSP keeps `script-src 'self'` with no `unsafe-eval`; `style-src 'unsafe-inline'` is accepted because Tiptap/ProseMirror inject a runtime style element and a few controls use inline style attributes. On Windows and Linux the print path uses an unsandboxed same-origin iframe with a scriptless `default-src 'none'` meta CSP and removes it immediately after printing; that deviation is compensated by the Rust ammonia pass, DOMPurify, and the per-document CSP because the engine must run `print()` on the frame's own window. macOS WebKit ignores `print()` from frames, so macOS prints the window natively (`print_webview`) while `@media print` shows only a sandboxed print-host frame sized to its content. See [CONTENT_BLOCKING.md](CONTENT_BLOCKING.md) and [THREAT_BLOCKING.md](THREAT_BLOCKING.md).

Distribution features are compile-time/runtime detected. Direct packages use signed GitHub updater manifests. Microsoft Store, Mac App Store, and Flatpak editions report store-managed updates and do not initialize or expose the Tauri updater.

On Windows the mailbox window is frameless with HTML caption controls and a native Snap-layout hit-test overlay over Maximize (the same WebView2 `HTMAXBUTTON` approach as IYERIS). Native application menus stay on macOS (system menu bar) and Linux (decorated GTK window). Windows must not call `app.set_menu`: muda's Win32 menubar is painted on `WM_NCACTIVATE` and shows through the transparent WebView2 as Postal Snap / File / Edit / Message / View. Mail keyboard shortcuts on Windows are handled in the React shell. Product right-click menus are HTML portals in the webview, not a native app menubar. `closeToTray` (default on) hides the window to a Windows notification-area icon or macOS menu bar extra instead of quitting; Linux ignores the field and still quits on close. On macOS a window closed to the menu bar also leaves the Dock (accessory activation policy) until it is reopened. A downloaded update installs quietly on quit (without relaunching) or, after the window has waited 60 seconds in the tray or menu bar (timed in Rust, since hidden webviews throttle timers), in the background; a short-lived `update-relaunch` marker in app data tells the relaunched process to start hidden.

Direct-download editions store the updater check cadence in `settings.json` as `updateCheckInterval` (startup plus every 6 hours by default). Store and Flatpak editions ignore that field and keep store-managed updates.

The typed event boundary includes sync state, folder-count, message-change, draft-sync, and outbox events. Event payloads contain opaque IDs and safe states, never message content or credentials.
